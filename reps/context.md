# Reps — how a real-world rep loop is designed here

Text drills train recognition and having a reply ready (rungs 1–2 of `../principles.md`),
not composure under real pressure (rung 3) — see `../research/`. Reps are the only place
this grove produces evidence instead of consuming it.

The procedure is the parent's: `../parents/behavior-rewiring/protocols/single-target-sprint.md`.
This file is the grove's instantiation of it — what a sprint here must decide, and the
discriminators that took a session to find. **The live sprint itself is not here:** it is
one practitioner's target, baseline and weekly numbers, so it lives in the private layer,
which orientation reports the location of. Read it on demand.

## What a sprint here has to decide

1. **The cue, as a replacement.** One line, `when <detectable social trigger>, I <one
   specified behavior>` — never "don't do X". The parent supplies the form; this grove
   supplies the trigger, from `../principles.md`'s two failure directions or from a
   pattern the bank flags as unfinished.
2. **Recognition-only, or not.** The parent sanctions recognition-only (notice the
   crossing, change nothing) as a legitimate first sprint, and it usually is. Check it
   against the practitioner first: if detection is already reliable, a recognition sprint
   trains an already trained capacity, and the sprint should target whatever is actually
   unknown instead.
3. **One active target.** The parent's detection-load argument caps this grove at a single
   active interception target however many failure modes `principles.md` lists. The rest
   go on a written queue. A sprint that watches for every failure mode is the failure the
   parent rules out.
4. **Do not add fields.** The log competes with the thing it measures.

## The discriminator problem, and the answer that works

Swallowing and declining-to-make-an-issue look identical from outside, and often from
inside. `../principles.md` names both failure directions, and the parent's
`open-questions.md` §4 warns that the introspective markers here flatter the practitioner.
So a sprint must not ask for that judgment in the moment.

**Use residue.** Not "did it feel effortful" but **is it still bugging me hours later.**
Declining costs nothing and leaves nothing; swallowing leaves residue. Ask for a count in
the moment and the sort afterwards — that is reportable without requiring honesty under
pressure, which is why it is the one being used.

## Capture — three surfaces, not a file in a repo

An earlier version of this loop assumed a git repo was a workable capture surface during
normal life. It isn't, and a log that doesn't get filled is not a weaker version of the
protocol — it is the absence of it. The pattern that works:

| When | Where | What |
|---|---|---|
| **During** the conversation | nowhere | Nothing. Capture in the moment costs the attention the thing itself needs. |
| **Right after** it ends | a phone buffer, one pinned note | One line, appended. A count and a sentence. Fifteen seconds. |
| **Weekly** | something physical the practitioner already opens | Read the week's lines and sort them. Write the numbers and what the sort showed. |
| **At the ruling** | the sprint's own file | Roll the weekly numbers in and write the ruling. Not before. |

**Why physical, and why not "Sundays."** Recording progress has its own effect on
attainment, and it is larger when the record is physical rather than a mental or purely
digital tally (`../parents/behavior-rewiring/sources.md` §8). And the best-evidenced lever
in the parent node is the cue-bound if-then plan — a trigger that already occurs beats a
date in a calendar, so the weekly rollup attaches to an existing habit rather than
inventing one.

**A bare count is not enough.** The sentence is what makes the weekly sort possible — in
seven days the numbers all look alike and only the sentence says which ones had residue.

## Schema

The rollup is the parent's catch-log, not a new one:

| Week ending | Baits counted | Declined clean | Swallowed (residue) | What the sort showed |
|---|---|---|---|---|

## Ruling

At the end of the window, write one of **extend / bank / abandon-or-reframe**, with the
reason, per `protocols/single-target-sprint.md` §6. A sprint whose outcome isn't recorded
teaches the next one nothing.
